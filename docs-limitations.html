Limitations

What the in-browser interpreter can and cannot do.

iframe / embed: the embed snippet creates a fully isolated terminal (its own Pyodide instance and Web Worker). It does not share the API key, history, or any state with this page — each embedded page load starts fresh. The embedded terminal has no "Set key" button; use set_key("...") inside it.
Async only: the browser has no blocking I/O, so every request must be awaited (await).
Streaming: stream=True is not supported by this shim yet.
Memory only: the API key and conversation live only in the current session's memory; they are lost on reload and are never persisted to disk.
CORS: the provider must allow browser requests. DeepSeek, OpenAI, OpenRouter and Groq do; self-hosted providers (e.g. Ollama) depend on your setup.
No sockets / threads: Pyodide in the browser has no raw sockets or threading; libraries that depend on them (e.g. the real openai/anthropic SDKs) cannot run here. This shim uses fetch instead.
