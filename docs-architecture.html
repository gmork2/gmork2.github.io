Architecture

How the in-browser interpreter works under the hood.

Data flow

Code runs in a Web Worker, not on the main thread, so long-running Python never freezes the UI.

Components

  • Main thread — terminal UI, SPA router, ENVIRONMENT panel.
  • Web Worker (llm-worker.js) — loads Pyodide and runs Python.
  • Pyodide — CPython compiled to WebAssembly.
  • pyfetch — the browser fetch API, used for HTTP to providers.

Message protocol

The terminal and worker communicate with postMessage:

MessageDirectionPurpose
runmain → workerexecute Python code
set-keymain → workerstore the API key
resetmain → workerclear the conversation
out / result / doneworker → mainoutput, result, completion
nsworker → mainnamespace snapshot for ENVIRONMENT

ENVIRONMENT snapshot

After each run, the worker serializes globals() (excluding modules and names starting with _) and sends it to the ENVIRONMENT panel.
